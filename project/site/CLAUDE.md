# Сайт — как устроен и по каким принципам строится

Публичный сайт: лендинг, каталог, блог, страницы услуг. Nuxt 4 с SSR, Tailwind 4, на основном домене. Нужен, только если сайт ищут в поиске и им делятся ссылкой. Нет такой задачи — этой папки в проекте нет.

Здесь — как строить этот сервис. Общее для проекта — `AGENTS.md` в корне.

## Почему SSR

Сервер отдаёт готовый HTML: поисковик видит текст, мессенджер собирает превью ссылки, первая загрузка быстрее. SPA поисковик видит пустой страницей. Админка с её логином — отдельное приложение (`admin/`), сайт с ней не смешиваем.

## Раскладка

```
app/
  pages/          страницы; тонкие
  components/     по папке на раздел: blog/ArticleCard.vue, catalog/ProductGrid.vue
  composables/    данные для страниц: useArticles, useCatalog; useApi; useSiteSeo
  utils/          чистые функции: даты, цены, форматы
  data/           тексты и списки сайта, которые не приходят из API
server/
  routes/         sitemap.xml, robots.txt
  api/            служебное: сброс кэша при публикации
  plugins/        заголовки кэша для браузера
scripts/
  check-architecture.mjs   сторож раскладки и размеров
```

## Кто что делает

Роли те же, что в админке: **API → `useApi` → composable → страница → компоненты.**

- **Страница** собирает экран из компонентов и задаёт SEO через `useSiteSeo`. В ней нет `$fetch`, расчётов и длинной разметки.
- **Компонент** — один блок страницы: шапка, карточка, форма заявки. Данные — через props.
- **Composable** грузит данные через `useAsyncData` и `useApi`. Тогда данные приходят в HTML с сервера, а не догружаются в браузере. Прямой `$fetch` или `useFetch` в странице и компоненте запрещён.
- **`app/data/`** — тексты и списки, которые не из API: преимущества, пункты меню, FAQ. Контент не пишется прямо в разметку компонентов.
- **`server/`** — только служебное: sitemap, robots, сброс кэша. Бизнес-логики и своей базы у сайта нет, данные — из API. Читать базу напрямую можно только по правилу из `AGENTS.md` («Архитектура»): только чтение, отдельный пользователь базы.

## Размеры и сторож

- Страница — до 200 строк, компонент — до 300. 600 — потолок.
- Длинная страница — это секции отдельными компонентами: `HeroSection.vue`, `PricesSection.vue`.
- `scripts/check-architecture.mjs` проверяет: нет `$fetch` и `useFetch` в страницах и компонентах, нет запросов в `utils/`, нет файлов длиннее 600 строк. Подключение — `"check:arch": "node scripts/check-architecture.mjs"` и `"check": "pnpm build && pnpm check:arch"` в `package.json`. `pnpm check` — перед каждым коммитом.

## SEO

- У каждой страницы — title, description, canonical и картинка для превью. Задаются одной своей обёрткой `useSiteSeo` (поверх `useSeoMeta`), а не россыпью мета-тегов.
- Новая страница: `useSiteSeo`, адрес в sitemap. Служебная (политика, превью, тестовые) — `noindex` и не в sitemap. Закрытое от поиска — в robots.txt.
- Структурированные данные — JSON-LD: `Organization` на главной, `Article` у статей, `Product` в каталоге.
- Адрес опубликованной страницы (slug) не меняется. Менять всё же нужно — сначала 301 со старого адреса.
- Новую страницу — на переобход: Яндекс Вебмастер и Google Search Console. Статьи API может отправлять сам при публикации через IndexNow.
- Коды подтверждения Вебмастера и Search Console — в env (`NUXT_PUBLIC_*`), а не в коде.

## Кэш и память

- Страницы кэшируются на сервере (`swr` в `routeRules`) с пределом LRU, например 500 страниц и 64 МБ. Ключ кэша включает `?query`: без предела скрипт с `/?x=1..3000` забьёт память.
- Браузеру — `Cache-Control: no-cache`: с `max-age` старый `_payload.json` подменял свежий HTML.
- При публикации API сбрасывает кэш сайта запросом с секретом (`NUXT_REVALIDATE_SECRET`).
- Редиректы и счётчики переходов в `swr` не клади: кэш их съест.

## Безопасность

- env читается при старте контейнера. В `NUXT_PUBLIC_*` — только публичное.
- Source map в прод не выкладывай.
- Форма заявки отправляет данные в API. У маршрута — лимит по IP, иначе спам-боты завалят базу.
- Шрифты и иконки — в бандле, без внешних CDN: из России они бывают недоступны, и страница грузится без них.
- `v-html` — только для своего проверенного HTML. Markdown из базы — с `html: false`.
