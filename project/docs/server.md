# Сервер и панель деплоя: защита и проверки перед запуском

Для VPS с Dokploy (Docker Swarm + Traefik). Порядок важен: сначала сервер и панель — через них получают всё (env с ключами, базы, root), потом приложения.

Правило для каждого шага: **команда проверки с ожидаемым выводом и команда отката.** Каждый шаг на сервере делается только с согласия владельца. Перед правкой конфига сохрани текущую версию.

Везде ниже `<IP>` — адрес сервера.

---

## С нуля: сервер, Dokploy, первое приложение

1. **VPS.** Ubuntu 24.04. Минимум для самого Dokploy — 2 ГБ памяти и 30 ГБ диска. Для продукта с базой бери от 4 ГБ. Один такой сервер держит несколько небольших продуктов. Продукт хранит персональные данные граждан России — сервер и хранилище бэкапов нужны в российском дата-центре (152-ФЗ, `AGENTS.md`, «Персональные данные и закон»).
2. **Свап.** На VPS с 2–4 ГБ памяти без свапа первый же скачок памяти убивает приложения и панель мгновенно: Linux снимает процесс OOM-killer'ом, а Dokploy не успевает перезапустить. Свап не заменяет лимиты памяти из раздела 8 — он даёт запас на пик и делает падение мягким. Под root:
   ```
   fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
   echo '/swapfile none swap sw 0 0' >> /etc/fstab
   sysctl vm.swappiness=10 && echo 'vm.swappiness=10' >> /etc/sysctl.conf
   ```
   Проверка: `swapon --show` — `/swapfile` с размером 2G, `free -h` — Swap не нулевой. Откат: `swapoff /swapfile && rm /swapfile`, строку из `/etc/fstab` и `vm.swappiness` из `/etc/sysctl.conf` убрать.
3. **Установка** под root:
   ```
   curl -sSL https://dokploy.com/install.sh | sh
   ```
   Открой `http://<IP>:3000` и создай учётку администратора.
4. **Домен панели.** A-запись `panel.<домен>` на `<IP>`. В настройках панели укажи этот домен и включи HTTPS. Дальше входи только по домену, а порт 3000 закрой (шаг 2 ниже).
5. **GitHub.** Подключи его в настройках панели (раздел Git). Так Dokploy видит приватные репозитории и сам деплоит на пуш.
6. **База.** Project → Create Service → Database → PostgreSQL. External Port оставь пустым. Включи бэкапы (шаг 6 ниже).
7. **Приложение** на каждую папку репозитория (`api/`, `admin/`):
   - Create Service → Application, источник — GitHub, ветка `main`;
   - Build Type — Dockerfile, Build Path — папка сервиса;
   - Watch Paths — та же папка, чтобы пуш в соседнюю не пересобирал это приложение;
   - Environment — env приложения, в том числе `DATABASE_URL` с внутренним именем базы;
   - Domains — домен приложения с HTTPS (Let's Encrypt);
   - включи автодеплой и нажми Deploy.

После этого пройди шаги ниже по порядку.

## 0. Что торчит наружу

- Сначала посмотри фаервол хостера. Группа с политикой DROP закрывает порты раньше сервера и изнутри не видна: `ufw status` при этом может показывать `inactive`.
- Со своего компьютера доступность проверять бесполезно, если твой адрес в списке разрешённых. Проверяй с адреса не из списка.
- Некоторые VPN принимают любое соединение сами, и `nc -z` показывает «открыто» на всех портах. Проверяй по ответу сервиса или с выключенным VPN.

```
ssh -o PreferredAuthentications=none root@<IP>
#   Permission denied (publickey,password) — пароль принимается, плохо
#   Permission denied (publickey)          — только ключ, хорошо

curl -s -o /dev/null -w '%{http_code}\n' http://<IP>:3000/
#   200 — панель открыта по голому HTTP, 000 — закрыта

# на сервере
docker service ls --format '{{.Name}} {{.Ports}}'
journalctl -u ssh --since "24 hours ago" -q | grep -c -E "Failed password|Invalid user"
```

Тысячи попыток подобрать пароль за сутки — нормальный фон для любого сервера в интернете.

## 1. Двухфакторка в панели

Панель — это root на сервере. В Dokploy в 2026 году вышло около десятка критичных уязвимостей, многие — для уже вошедшего пользователя.

- Profile → Two-Factor Authentication → Enable 2FA, код в любом TOTP-приложении.
- Резервные коды сохрани отдельно: в менеджер паролей или на бумагу.
- Выйди и войди заново — проверка.

## 2. Закрыть порт панели 3000

Docker открывает свои порты в обход ufw, поэтому ufw здесь не поможет.

```
grep -A3 "servers:" /etc/dokploy/traefik/dynamic/dokploy.yml   # должно быть url: http://dokploy:3000
docker service update --publish-rm "published=3000,target=3000,mode=host" dokploy
# проверка: http://<IP>:3000 не отвечает, домен панели открывается
# откат:    docker service update --publish-add "published=3000,target=3000,mode=host" dokploy
```

Переустановка Dokploy откроет порт снова — повтори шаг.

**Панель — только со своих адресов.** Двухфакторка не спасает от уязвимостей, которые срабатывают до входа, а панель — это root на сервере. Пусти её только со своих адресов:
1. Settings → Traefik → `middlewares.yml`, определение — первым:
   ```yaml
       panel-allowlist:
         ipAllowList:
           sourceRange:
             - "<твой адрес>/32"
             - "<адрес твоего VPN>/32"
   ```
   В Traefik v2 middleware называется `ipWhiteList`.
2. В `/etc/dokploy/traefik/dynamic/dokploy.yml` у маршрута панели допиши `panel-allowlist` к его `middlewares`.
3. Проверка: с телефона без Wi-Fi панель отвечает 403, со своего адреса открывается. Откат — убери `panel-allowlist` из `middlewares` маршрута.

Нет постоянного адреса — заходи через свой VPN и впиши его адрес.

## 3. SSH только по ключу

1. Ключи со всех своих компьютеров — **до** того, как выключать пароль: `ssh-keygen -t ed25519`, затем `ssh-copy-id -i ~/.ssh/id_ed25519.pub root@<IP>`.
2. Посмотри, кто вообще входит: `journalctl -u ssh --since "30 days ago" -q | grep Accepted`. Если кто-то входит по паролю (коллега, скрипт деплоя), сначала добавь его ключ.
3. Выключи пароль файлом `00-…`. Он читается раньше `50-cloud-init.conf`, а в sshd побеждает первое значение:
   ```
   ssh root@<IP> 'printf "PasswordAuthentication no\nKbdInteractiveAuthentication no\nPermitRootLogin prohibit-password\nPubkeyAuthentication yes\nMaxAuthTries 3\n" > /etc/ssh/sshd_config.d/00-hardening.conf && sshd -t && systemctl reload ssh && echo OK'
   ```
4. Проверь **новым** соединением:
   ```
   ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no root@<IP>
   #   Permission denied (publickey)
   ```
5. Запасной вход — консоль в панели хостера: настройки SSH её не касаются. Пароль root не забывай. Откат из консоли: `rm /etc/ssh/sshd_config.d/00-hardening.conf && systemctl reload ssh`.

## 4. fail2ban

```
ssh root@<IP> 'apt-get update -qq && DEBIAN_FRONTEND=noninteractive apt-get install -y -qq fail2ban && systemctl enable --now fail2ban && sleep 3 && fail2ban-client status sshd'
```

По умолчанию — 5 неудач за 10 минут дают бан на 10 минут. Снять бан: `fail2ban-client set sshd unbanip <адрес>`.

## 5. Базы не наружу

- Лучше всего — пустое поле External Port у базы. Приложения ходят в неё внутри сети Docker (`<appName>:5432`).
- Перед закрытием порта проверь, нет ли приложений, которые подключаются по внешнему адресу. Сначала переведи их на внутренний.
- Внешний порт нужен разработке — значит, разработке нужна своя локальная база (Postgres в Docker). В боевую ходи только когда надо: на время открой порт или зайди через терминал базы в панели.
- Если порт всё же открыт, то только за фаерволом хостера с политикой DROP. Помни: разрешённый пул провайдера (`/21` — это 2048 адресов) или выход общего VPN пускают и чужих.
- У разработки, сайта и API — разные пользователи базы. Публичный сайт, который только читает, получает SELECT только на свои таблицы.

## 6. Бэкапы

- Ежедневный дамп базы на хранилище **вне этого сервера**. В Dokploy: S3 Destinations в настройках, затем Backups у базы.
- Храни хотя бы 14 последних.
- Восстановление проверь хотя бы раз: подними дамп в чистую локальную базу и открой в ней приложение. Непроверенный бэкап — не бэкап.
- **Взломанный сервер не должен стереть бэкапы.** Бакет — с версионированием и правилом жизненного цикла: старые версии удаляются через 30 дней. Ключ, который дан Dokploy, — без права удалять версии. Тогда Dokploy чистит старые бэкапы как обычно, а стереть их насовсем с сервера нельзя. Умеет хранилище блокировку объектов (Object Lock) — ещё надёжнее.
- **Честно про потери:** ежедневный дамп — это до суток потерянных данных при аварии. Нельзя терять столько — бэкап чаще или непрерывный архив журнала Postgres (WAL, например pgBackRest или wal-g).
- Персональные данные граждан России — хранилище бэкапов тоже в России.
- Файлы пользователей — в S3 с версионированием, а не на диске сервера.

## 7. Обновления

- Ubuntu: `unattended-upgrades` для обновлений безопасности.
- Dokploy: перед обновлением прочитай заметки к релизу. После обновления проверь шаг 2: порт 3000 мог открыться снова.
- Базовые образы (`node:24-alpine`, образ Postgres) обновляй хотя бы раз в квартал.

## 8. Лимиты памяти и CPU у каждого контейнера

Без лимита одно приложение с утечкой роняет соседей и саму панель. С лимитом падает только оно, и Dokploy его перезапускает.

- Панель: приложение → Advanced → Resources. `memoryLimit` — в байтах (512 МБ = `536870912`), `cpuLimit` — в миллиардных долях ядра (1 ядро = `1000000000`).
- Лимит включается только при следующем деплое.
- Подбирай по пику под нагрузкой, а не по `docker stats` в покое:
  ```
  c=$(docker ps -q --no-trunc -f name=^<сервис>\\. | head -1)
  cat /sys/fs/cgroup/system.slice/docker-$c.scope/memory.peak
  ```

## 9. Лимит запросов с одного IP в Traefik

1. Settings → Traefik → `middlewares.yml`. Добавь определение **первым**: ссылка на несуществующий middleware ломает маршрут.
   ```yaml
       ratelimit-public:
         rateLimit:
           average: 30
           period: 1s
           burst: 100
   ```
2. У маршрутов приложения с `entryPoints: [websecure]` впиши `middlewares: [ratelimit-public]`.
   - Не вешай лимит на всю точку входа: он заденет вебхуки.
   - Не делай его строгим: мобильные операторы сажают тысячи людей на один IP.
3. Проверь:
   ```
   curl -s -Z --parallel-max 100 --http2 "https://<домен>/robots.txt?n=[1-400]" -o /dev/null -w '%{http_code}\n' | sort | uniq -c
   #   часть 200, остальные 429
   ```
   Обычный `xargs -P 50 curl` может не набрать скорость. То, что через него всё прошло, не значит, что лимит не работает.
4. Dokploy пересобирает маршруты при смене доменов приложения, и middleware пропадает. После такой смены впиши его снова.

## 10. Env через API панели

- `application.saveEnvironment` перезаписывает env целиком. Передавай весь env вместе с прежними `buildArgs`, иначе затрёшь.
- Переменная, сохранённая во время идущего деплоя, может в него не попасть. Проверь через `docker service inspect` и передеплой.

## 11. Проверки приложения перед запуском

| Что | Как проверить | Ожидаемо |
|---|---|---|
| Все закрытые маршруты API за входом | запрос к API без куки — к каждому маршруту, кроме публичных (вход, `/health`, вебхуки). Страницы админки не проверяй: SPA на любой адрес отдаёт 200 | 401 |
| Подделка IP | 20 неверных входов подряд с заголовком `X-Forwarded-For: 1.2.3.4` | 429 по твоему настоящему IP, в логе входа — он, а не 1.2.3.4 |
| CSRF | `curl -X POST <api>/… -H "Origin: https://evil.example"` | 403 |
| CORS | заголовки ответа | свои адреса, нигде нет `*` с credentials |
| Секреты не в браузере | исходник страницы, `window.__NUXT__.config` | нет ключей |
| Source map | `<сайт>/_nuxt/<файл>.js.map` | 404 |
| История git | команда ниже | пусто: ни ключей, ни паролей, ни токенов за всю историю |
| Лимит тела | POST на 3 МБ, в том числе `Transfer-Encoding: chunked` | 413 |
| Лимит входа | 20 неверных паролей подряд | 429 |
| Заголовки | команда ниже | HSTS есть, у админки DENY, X-Powered-By нет |
| Кэш SSR | 3000 запросов `/?x=N` и замер памяти | память не растёт без предела |
| Healthcheck | остановить базу и запросить `/health` | не `ok` |

Команды для таблицы. Внутри таблицы их не держим: в сыром файле знак `|` там приходится экранировать, и скопированная команда перестаёт работать.

```
# История git: точные приметы секретов — приватный ключ, адрес базы с паролем,
# токен Telegram-бота, ключи OpenAI, Anthropic, AWS. Локальные адреса разработки не в счёт.
# Новые коммиты то же самое проверяет git-хук, эта команда — для уже накопленной истории.
git log --all -p | grep -E 'BEGIN [A-Z ]*PRIVATE KEY|postgres(ql)?://[^:/@ ]+:[^@/ ]+@|[0-9]{8,10}:AA[A-Za-z0-9_-]{33}|sk-(proj-|ant-)?[A-Za-z0-9_-]{20,}|AKIA[0-9A-Z]{16}' | grep -v -E '@(localhost|127\.0\.0\.1|db|postgres)[:/]'

# Заголовки безопасности
curl -sI https://<домен>/ | grep -i -E "strict-transport|x-frame|content-security|x-powered"
```

Глубже историю проверяет gitleaks — отдельная программа, ставится один раз.

## 12. Наблюдение за сервером

Один VPS чаще всего ложится не от нагрузки, а от заполненного диска. А о том, что сайт лежит, лучше узнать раньше клиентов.

- **Внешний пинг.** Сервис снаружи сервера раз в минуту открывает `https://api.<домен>/health` и главную сайта и пишет в Telegram, если они не отвечают. Подойдёт любой сервис проверки доступности или второй дешёвый сервер. Монитор на том же сервере бесполезен: он упадёт вместе с ним.
- **Ошибки приложения.** Логи — в Dokploy у каждого приложения, у строк префикс подсистемы (`[auth]`, `[worker:payout]`), по ним удобно искать. Хочешь видеть ошибки сразу — Sentry-совместимый сборщик, например GlitchTip, его можно поднять в том же Dokploy.
- **Диск:**
  ```
  df -h /            # больше 80 % — разбирайся
  docker system df   # сколько занимают образы, контейнеры, тома
  ```
- **Логи контейнеров** без предела растут бесконечно. Предел — в `/etc/docker/daemon.json` (файл уже есть — допиши ключи, не затирай):
  ```json
  { "log-driver": "json-file", "log-opts": { "max-size": "10m", "max-file": "3" } }
  ```
  Потом `systemctl restart docker`. Это перезапустит все контейнеры — делай в тихое время. Предел действует на контейнеры, созданные после перезапуска: следующая выкладка его подхватит.
- **Старые образы** копятся после каждой сборки. Включи очистку Docker в настройках сервера в Dokploy или поставь в cron раз в сутки `docker image prune -af --filter "until=168h"`.
- Тома не чисти: `docker volume prune` и `docker system prune --volumes` стирают данные баз.

## 13. Видео и стримы

- В кадре не должно быть панели с env и базами, `.env` и терминала, в котором читаются файлы с ключами.
- Засветил ключ — сразу перевыпусти.
- Адрес API прятать не нужно: его защищают вход и токены, а не секретность адреса. Панель — другое дело, её пускай только со своих адресов (шаг 2).
