# Правила, с которыми нейросеть строит нормальный продукт

![Правила, с которыми нейросеть строит нормальный продукт: масштаб, бэкенд, фронт и база отдельно, 27 болезней вайбкодинга, защита базы, Dokploy и 152-ФЗ](assets/cover.png)

Для тех, кто делает продукт с Claude Code, Cursor или Codex и не считает себя программистом.

Без правил нейросеть собирает проект «как в среднем по интернету»:
- вся логика в одном файле на 1500 строк, расчёты и запросы к базе прямо в обработчиках;
- `fetch` в каждом компоненте, ключ от базы или OpenAI прямо во фронте;
- права только на кнопках: спрятал кнопку — значит, защищено;
- Kubernetes и пять микросервисов для CRM, которой пользуются восемь человек;
- «давай сбросим базу» — и боевые данные пропали.

Здесь — правила, по которым нейросеть строит проект так, как его строят после того, как наступили на все эти грабли. Они собраны из живых проектов: CRM с платежами и выплатами, чат-платформы для продаж, сайта с админкой. Почти за каждым правилом стоит случай, когда что-то сломалось.

## Что это даёт

- **Нейросеть знает масштаб.** CRM на восемь человек не превратится в банк: никаких Kubernetes и микросервисов без причины.
- **Проект разложен по полочкам.** Отдельно бэкенд, фронт и база. У каждой части свой файл с правилами: что где лежит и что куда нельзя.
- **Нет переростков и логики не на своём месте.** Роут только принимает запрос, логика — в сервисах, на фронте в API ходят только composables, файл — до 300 строк. Главное из этого — запросы к базе и внешним API не из своего слоя, файлы длиннее 600 строк — перед каждым коммитом проверяет скрипт.
- **Безопасность по-взрослому.** Секреты, пароли, права, проверка ввода, защита от типовых атак — с первого дня. Ключи и пароли не уедут в git: это проверяет git-хук.
- **Закон учтён.** Данные клиентов — по 152-ФЗ: сервер в России, согласие на формах, в зарубежный ИИ — без персональных данных.
- **База защищена от самой нейросети** — в Claude Code. Хук не даст ей стереть базу, накатить миграцию не туда или обойти проверки. В Cursor и Codex защиту держат правила.
- **Деплой без DevOps.** Один сервер с Dokploy: пушишь в `main`, он сам собирает и выкладывает.

## Как пользоваться

### Новый проект

1. Создай пустую папку и открой в ней Claude Code, Cursor или Codex.
2. Скопируй сообщение, допиши, что хочешь сделать, и отправь нейросети:

   ```text
   Установи в эту папку правила разработки из
   https://github.com/Skamatoz/vibecoding-rules: скопируй содержимое
   папки project/ в корень, ничего моего не затирая. Если .gitignore
   или .claude/settings.json уже есть — допиши в них недостающее.
   Сделай git init и включи git-хук сторожа:
   git config core.hooksPath .githooks
   Потом прочитай AGENTS.md и CLAUDE.md.

   Хочу сделать: (опиши продукт: что он делает, для кого, сколько
   примерно пользователей, есть ли оплата).

   Заполни в CLAUDE.md масштаб и сервисы и спроси, чего не хватает.
   Потом предложи, какие будут таблицы, экраны и маршруты.
   Код пока не пиши.
   ```

3. Ответь на вопросы, посмотри план. Дальше: «Делай по плану, по одному шагу».

Если удобнее через терминал:

```
npx degit Skamatoz/vibecoding-rules/project my-app
cd my-app
git init
git config core.hooksPath .githooks
```

### Существующий проект

Скопируй и отправь нейросети:

```text
Установи в этот проект правила разработки из
https://github.com/Skamatoz/vibecoding-rules: скопируй содержимое
папки project/ в корень, ничего моего не затирая. Мои .gitignore
и .claude/settings.json не заменяй, а допиши в них недостающее
из правил. Если мои папки бэкенда и фронта называются иначе,
положи AGENTS.md, CLAUDE.md и scripts/ из api/ и admin/ в мои папки.
Включи git-хук сторожа:
git config core.hooksPath .githooks

Прочитай AGENTS.md в корне и в папках сервисов и сверь с ними
проект. Составь список болезней из раздела «Болезни» и других
расхождений по важности: сначала безопасность и данные, потом
остальное. Ничего не меняй.
```

Дальше чини по одному пункту за раз.

### Обновить правила

Правила меняются: что исправлено — в [`CHANGELOG.md`](CHANGELOG.md), версия — в начале `AGENTS.md`.

Скопируй и отправь нейросети:

```text
Обнови правила разработки из
https://github.com/Skamatoz/vibecoding-rules. Сравни версию
в моём AGENTS.md с последней. Общую часть AGENTS.md и файлов
сервисов (выше черты ---), хук, git-хук и сторожей замени новыми.
Своё ниже черты и CLAUDE.md в корне не трогай.
Скажи, что поменялось.
```

## Что внутри

Всё, что копируется в проект, лежит в папке [`project/`](project/):

| Файл | Что это |
|---|---|
| [`AGENTS.md`](project/AGENTS.md) | общие правила: масштаб, болезни и как их не допустить, архитектура, код, база, секреты, персональные данные, деплой |
| [`CLAUDE.md`](project/CLAUDE.md) | описание твоего проекта: масштаб и сервисы. Нейросеть заполнит его сама |
| [`api/AGENTS.md`](project/api/AGENTS.md) | как строить бэкенд: роуты, сервисы, middleware, воркеры, вход и права, деньги, вебхуки |
| [`api/prisma/AGENTS.md`](project/api/prisma/AGENTS.md) | как проектировать базу: таблицы, связи, индексы, статусы, деньги, миграции |
| [`admin/AGENTS.md`](project/admin/AGENTS.md) | как строить админку или CRM (SPA): страницы, компоненты, composables, плагины, middleware |
| [`site/AGENTS.md`](project/site/AGENTS.md) | как строить публичный сайт (SSR): то же плюс SEO и кэш. Нужен, только если есть сайт для поиска |
| `*/CLAUDE.md` | одна строка `@AGENTS.md`: через неё Claude Code читает правила сервиса |
| `*/scripts/check-architecture.mjs` | сторож. На бэкенде: роут не лезет в базу и во внешние API, `lib/` не знает о сервисах. На фронте: страницы и компоненты не делают запросов сами, `utils/` — чистые функции. Везде: файл не длиннее 600 строк |
| [`.githooks/pre-commit`](project/.githooks/pre-commit) | git-хук перед каждым коммитом: ищет ключи, пароли и `.env`, запускает сторожа. Нарушение — коммит не проходит |
| [`.github/workflows/check.yml`](project/.github/workflows/check.yml) | те же сторожа в GitHub на каждый пуш — на случай, если git-хук где-то не включён |
| `*/Dockerfile`, `.dockerignore`, `.env.example`, `.npmrc` | готовая сборка для Dokploy и настройки, без которых нейросеть ошибается. Dockerfile собирается, когда в папке появятся `package.json` и lockfile — их создаст нейросеть |
| [`.gitignore`](project/.gitignore) | `.env` с ключами, `node_modules` и сборка не попадают в git |
| [`docker-compose.yml`](project/docker-compose.yml) | база для разработки на твоём компьютере. Боевая живёт в Dokploy, эта — чтобы нейросеть экспериментировала не на ней |
| [`.claude/hooks/guard-db.mjs`](project/.claude/hooks/guard-db.mjs) | хук Claude Code: блокирует команды, которые могут стереть базу или обойти проверки |
| [`docs/server.md`](project/docs/server.md) | сервер с нуля: VPS, Dokploy, защита, бэкапы, наблюдение, проверки перед запуском |

## Как это работает

- **`AGENTS.md` в корне нейросеть читает всегда.** Codex и Cursor находят его сами, Claude Code — через ссылку в `CLAUDE.md`.
- **`AGENTS.md` в папке сервиса** — правила этого сервиса. Codex и Cursor читают его, когда работают в этой папке, Claude Code — через `CLAUDE.md` рядом. Поэтому правила бэкенда нейросеть видит, когда пишет бэкенд, а правила базы — когда правит схему.
- **Сторож** — обычный скрипт, его запускает git-хук перед каждым коммитом и GitHub на каждый пуш. Нейросеть иногда нарушает правила из текста, а скрипт нарушение не пропустит: коммит не проходит, и она чинит код. Проверяет он не всё из правил, а самое частое и вредное. Остальное держится на тексте правил.
- **Хук** срабатывает перед каждой командой нейросети. Опасное для базы — `db push`, сброс, ручной SQL, правка миграций — он блокирует и объясняет, как сделать правильно. Работает в Claude Code.

## Стек

TypeScript везде, Node 24, Hono + Prisma 6 + PostgreSQL на бэкенде, Nuxt + Nuxt UI на фронте, Docker и Dokploy для деплоя. Всё популярное и скучное: нейросеть знает это хорошо и не выдумывает.

Prisma ставится только с номером версии: `prisma@6`. Без номера сейчас приедет тестовая восьмая, а седьмая устроена иначе, и правила написаны не под неё.

Другой стек — принципы те же: масштаб, слои, размеры, безопасность, база. Файлы сервисов написаны под Hono и Nuxt, но нейросеть перенесёт их на твой стек, если попросить.

## Сервер

Нет сервера — `docs/server.md`, раздел «С нуля»: аренда VPS, установка Dokploy одной командой, первое приложение. Сервер уже есть — пройди там шаги по порядку: двухфакторка и вход в панель только со своих адресов, SSH только по ключу, база не наружу, бэкапы, которые взломщик не сотрёт, наблюдение за диском и доступностью. Хранишь данные клиентов из России — сервер нужен в России. Каждый шаг можно отдать нейросети, но на сервере она делает только то, на что ты дал согласие.
