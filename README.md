# Правила для нейросети: чтобы она собирала нормальный проект, а не ерунду

Для тех, кто делает продукт с Claude Code, Cursor или Codex и не считает себя программистом.

Без правил нейросеть собирает проект «как в среднем по интернету»:
- вся логика в одном файле на 1500 строк, расчёты и запросы к базе прямо в обработчиках;
- `fetch` в каждом компоненте, ключ от базы или OpenAI прямо во фронте;
- права только на кнопках: спрятал кнопку — значит, защищено;
- Kubernetes и пять микросервисов для CRM, которой пользуются восемь человек;
- «давай сбросим базу» — и боевые данные пропали.

Здесь — правила, по которым нейросеть строит проект так, как его строят после того, как наступили на все эти грабли. Они собраны из живых проектов: CRM с платежами и выплатами, чат-платформы для продаж, сайта с админкой. Почти за каждым правилом стоит случай, когда что-то сломалось.

## Что это даёт

- **Нейросеть знает масштаб.** CRM на восемь человек не превратится в банк: никаких Kubernetes и микросервисов без причины.
- **Проект разложен по полочкам.** Отдельно бэкенд, фронт и база. У каждой части свой файл с правилами: что где лежит и что куда нельзя.
- **Нет переростков и логики не на своём месте.** Роут только принимает запрос, логика — в сервисах, на фронте в API ходят только composables, файл — до 600 строк. Это проверяет скрипт перед каждым коммитом.
- **Безопасность по-взрослому.** Секреты, пароли, права, проверка ввода, защита от типовых атак — с первого дня.
- **База защищена от самой нейросети.** Хук не даст ей стереть базу или накатить миграцию не туда.
- **Деплой без DevOps.** Один сервер с Dokploy: пушишь в `main`, он сам собирает и выкладывает.

## Как пользоваться

### Новый проект

1. Создай пустую папку и открой в ней Claude Code, Cursor или Codex.
2. Отправь нейросети сообщение:

> Установи в эту папку правила разработки из https://github.com/Skamatoz/vibecoding-rules: скопируй содержимое папки `project/` в корень, ничего моего не затирая. Потом прочитай AGENTS.md и CLAUDE.md.
>
> Хочу сделать: *(опиши продукт: что он делает, для кого, сколько примерно пользователей, есть ли оплата)*.
>
> Заполни в CLAUDE.md масштаб и сервисы и спроси, чего не хватает. Потом предложи, какие будут таблицы, экраны и маршруты. Код пока не пиши.

3. Ответь на вопросы, посмотри план. Дальше: «Делай по плану, по одному шагу».

Если удобнее через терминал — `npx degit Skamatoz/vibecoding-rules/project my-app` создаст папку `my-app` с правилами.

### Существующий проект

> Установи в этот проект правила разработки из https://github.com/Skamatoz/vibecoding-rules: скопируй содержимое папки `project/` в корень, ничего моего не затирая. Если мои папки бэкенда и фронта называются иначе, положи CLAUDE.md из `api/` и `admin/` в мои папки.
>
> Прочитай AGENTS.md и CLAUDE.md сервисов и сверь с ними проект. Составь список болезней из раздела «Болезни» и других расхождений по важности: сначала безопасность и данные, потом остальное. Ничего не меняй.

## Что внутри

Всё, что копируется в проект, лежит в папке [`project/`](project/):

| Файл | Что это |
|---|---|
| [`AGENTS.md`](project/AGENTS.md) | общие правила: масштаб, болезни и как их не допустить, архитектура, код, база, секреты, деплой |
| [`CLAUDE.md`](project/CLAUDE.md) | описание твоего проекта: масштаб и сервисы. Нейросеть заполнит его сама |
| [`api/CLAUDE.md`](project/api/CLAUDE.md) | как строить бэкенд: роуты, сервисы, middleware, воркеры, вход и права, деньги, вебхуки |
| [`api/prisma/CLAUDE.md`](project/api/prisma/CLAUDE.md) | как проектировать базу: таблицы, связи, индексы, статусы, деньги, миграции |
| [`admin/CLAUDE.md`](project/admin/CLAUDE.md) | как строить админку или CRM (SPA): страницы, компоненты, composables, плагины, middleware |
| [`site/CLAUDE.md`](project/site/CLAUDE.md) | как строить публичный сайт (SSR): то же плюс SEO и кэш. Нужен, только если есть сайт для поиска |
| `*/scripts/check-architecture.mjs` | сторож: перед коммитом проверяет, что код разложен по правилам и нет файлов-переростков |
| `*/Dockerfile`, `.dockerignore`, `.env.example`, `.npmrc` | готовая сборка для Dokploy и настройки, без которых нейросеть ошибается |
| [`docker-compose.yml`](project/docker-compose.yml) | база для разработки на твоём компьютере. Боевая живёт в Dokploy, эта — чтобы нейросеть экспериментировала не на ней |
| [`.claude/hooks/guard-db.mjs`](project/.claude/hooks/guard-db.mjs) | хук Claude Code: блокирует команды, которые могут стереть базу |
| [`docs/server.md`](project/docs/server.md) | сервер с нуля: VPS, Dokploy, защита, бэкапы, проверки перед запуском |

## Как это работает

- **`AGENTS.md` нейросеть читает всегда.** Codex и Cursor находят его сами, Claude Code — через ссылку в `CLAUDE.md`.
- **CLAUDE.md в папке сервиса Claude Code подгружает сам,** когда работает с файлами этой папки. Поэтому правила бэкенда она видит, когда пишет бэкенд, а правила базы — когда правит схему.
- **Сторож** — обычный скрипт. Нейросеть иногда нарушает правила из текста, а скрипт нарушение не пропустит: `pnpm check` не проходит, и она чинит код.
- **Хук** срабатывает перед каждой командой нейросети. Опасное для базы — `db push`, сброс, ручной SQL, правка миграций — он блокирует и объясняет, как сделать правильно. Работает в Claude Code.

## Стек

TypeScript везде, Hono + Prisma + PostgreSQL на бэкенде, Nuxt + Nuxt UI на фронте, Docker и Dokploy для деплоя. Всё популярное и скучное: нейросеть знает это хорошо и не выдумывает.

Другой стек — принципы те же: масштаб, слои, размеры, безопасность, база. Файлы сервисов написаны под Hono и Nuxt, но нейросеть перенесёт их на твой стек, если попросить.

## Сервер

Нет сервера — `docs/server.md`, раздел «С нуля»: аренда VPS, установка Dokploy одной командой, первое приложение. Сервер уже есть — пройди там шаги по порядку: двухфакторка в панели, закрытый порт панели, SSH только по ключу, база не наружу, бэкапы. Каждый шаг можно отдать нейросети, но на сервере она делает только то, на что ты дал согласие.
