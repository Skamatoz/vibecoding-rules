# Правила для ИИ-ассистента: нормальный продукт вместо ерунды

Нейросеть не знает, что вы делаете: CRM на восемь человек или банк на миллион клиентов. Поэтому она ошибается в обе стороны сразу.

- **Там, где можно проще, усложняет.** Микросервисы, Kubernetes, Kafka, Redis, пять слоёв абстракций — для продукта, которым пользуется один отдел.
- **Там, где нужна строгость, упрощает.** `req.body` целиком в базу, пароль в логах, ошибка со стеком наружу, права только на кнопках, `prisma db push` в боевую базу, вся логика в одном роуте на 800 строк.

Этот набор правил исправляет и то и другое. Он собран из живых проектов: CRM с платежами и выплатами, чат-платформы для продаж, сайта с админкой. Почти за каждым правилом стоит случай, когда что-то сломалось: стёртая боевая база, двойные уведомления при деплое, платная проверка, которая сработала 12 раз вместо одного, выплата, которая 17 часов висела без единой ошибки.

## Четыре главные идеи

1. **Скажи нейросети масштаб.** В CLAUDE.md проекта есть раздел «Масштаб»: кто пользуется, сколько данных, есть ли деньги и персональные данные. Например: «8 сотрудников, 50 тысяч сделок в год, оплата через ЮKassa». Прочитав это, ассистент не станет строить корпорацию.
2. **Один сервер и Dokploy, а не Kubernetes.** Dokploy — бесплатная панель, которая ставится на VPS одной командой. Пушишь в `main` — она сама собирает и выкладывает, выпускает HTTPS, поднимает Postgres и делает бэкапы. Для небольшого продукта это всё, что дал бы Kubernetes, без необходимости в нём разбираться.
3. **Код разложен одинаково и не разрастается.**
   - Роут только принимает запрос и зовёт сервис, вся логика — в сервисах.
   - На фронте в API ходят только composables, страница лишь собирает экран.
   - Сайт делается на SSR, а то, что за логином, — на SPA.
   - Файл длиннее 600 строк не пропускает сторож.

   Тогда любая следующая сессия ИИ находит нужное место и не ломает соседнее.
4. **Безопасность и данные — по-взрослому при любом размере.** Маленький продукт — это меньше серверов, а не меньше защиты. Утечка клиентской базы из маленькой CRM — такая же утечка.

## Что внутри

| Файл | Что там |
|---|---|
| `AGENTS.md` | главные правила для ассистента: масштаб, стек, архитектура, устройство кода, данные, безопасность, деньги, вебхуки, фоновые задачи, фронт, деплой |
| `templates/` | пример проекта: CLAUDE.md, локальная база, Dockerfile, env и сторож слоёв и размеров для API, админки (SPA) и сайта (SSR) |
| `docs/server.md` | сервер с нуля: VPS, Dokploy, первое приложение, защита, бэкапы, проверки перед запуском |
| `hooks/` | хук для Claude Code, который не даёт ассистенту стереть базу |

Стек по умолчанию: TypeScript везде, Hono + Prisma + PostgreSQL на бэкенде, Nuxt + Nuxt UI на фронте, Docker и Dokploy для деплоя. Всё популярное и скучное: нейросеть знает это хорошо и не выдумывает.

## Быстрый старт

Скопируй правила в корень своего проекта:

```
git clone --depth 1 https://github.com/Skamatoz/vibecoding-rules /tmp/ai-rules
cp /tmp/ai-rules/AGENTS.md .
cp -n /tmp/ai-rules/templates/CLAUDE.md CLAUDE.md
mkdir -p docs .claude/hooks
cp /tmp/ai-rules/docs/server.md docs/
cp /tmp/ai-rules/hooks/guard-db.mjs .claude/hooks/
cp -n /tmp/ai-rules/hooks/settings.json .claude/settings.json
```

Новый проект — возьми ещё заготовки сервисов и локальную базу. Лишнее, например `site/` без сайта, потом удали:

```
cp -Rn /tmp/ai-rules/templates/api /tmp/ai-rules/templates/admin /tmp/ai-rules/templates/site /tmp/ai-rules/templates/docker-compose.yml .
```

`cp -n` не трогает файлы, которые уже есть. Если `.claude/settings.json` у тебя уже был, допиши в него блок из `hooks/settings.json` руками.

Дальше смотри, какой у тебя инструмент:
- **Claude Code** читает `CLAUDE.md`, а ссылка `@AGENTS.md` в нём подключает общие правила. Хук работает только здесь.
- **Codex и Cursor** читают `AGENTS.md` из корня сами. Описание своего проекта всё равно держи в `CLAUDE.md` и попроси ассистента его прочитать.

`AGENTS.md` не правь под проект. Всё своё — масштаб, адреса, решения, подводные камни — пиши в `CLAUDE.md`. Тогда новую версию правил можно просто скопировать поверх.

### Новый проект

Первое сообщение ассистенту:

> Прочитай AGENTS.md. Делаем <что за продукт и для кого>. Масштаб: <сколько пользователей, сколько данных, есть ли оплата и персональные данные>. В CLAUDE.md сейчас пример — перепиши его под наш проект, начни с «Масштаба» и спроси, чего не хватает. Потом предложи состав: какие сервисы, таблицы, маршруты, страницы — и объясни, почему сервисов столько. Код пока не пиши.

### Существующий проект

> Прочитай AGENTS.md и сверь с ним этот проект. Составь список расхождений по важности: сначала безопасность и данные, потом лишняя сложность, потом остальное. Ничего не меняй.

Дальше чини по одному пункту за раз, и после каждого — сборка.

## Красные флаги

Если ассистент предлагает что-то из этого, останови его и спроси, какую измеренную проблему это решает:

- Kubernetes, Helm, Terraform, свой CI для выкладки;
- отдельный сервис на платежи, чат или уведомления при общей базе;
- Redis, Kafka, RabbitMQ, Elasticsearch «для масштабирования»;
- GraphQL, микрофронтенды, event sourcing, «чистую архитектуру» с репозиториями и use-case-классами;
- логику и запросы к базе прямо в роуте, `$fetch` прямо в компоненте, файл на 800 строк;
- публичный сайт на SPA: поисковик увидит пустую страницу;
- «давай сбросим базу», `prisma db push`, правку файлов миграций;
- ключ в коде, во фронте или в `NUXT_PUBLIC_*`;
- проверку прав только на фронте.

## Сервер

Нет сервера — `docs/server.md`, раздел «С нуля». Сервер уже есть — пройди там шаги по порядку: двухфакторка в панели, закрытый порт панели, SSH только по ключу, fail2ban, база не наружу, бэкапы, лимиты контейнерам. Каждый шаг можно отдать ассистенту: в файле есть команды проверки и отката. Но на сервере он делает только то, на что ты дал согласие.
